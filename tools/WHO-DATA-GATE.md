# WHO-data gate

acmacs-f is **public code**. WHO Collaborating Centre data (strain names, serum ids,
titres, sequences, clade assignments of real viruses) is **private** and lives in a
separate private data repository, never here. A leak to a public repo is permanent.

The gate enforces that mechanically. It is copied from ae (`ae/tools/who-data-gate.py`,
ae commit `0fd379b`, 24th September 2026). The full rationale and rule descriptions are in
ae's `tools/WHO-DATA-GATE.md`. Where the script's messages say `ae`, read `acmacs-f`.

## Install (once per clone)

```sh
git config core.hooksPath .githooks
```

| Hook | Scans | Command |
|---|---|---|
| `pre-commit` | staged file contents (the index) | `who-data-gate.py --staged --strict` |
| `commit-msg` | the commit message | `who-data-gate.py --message-file … --strict` |
| `pre-push` | every commit being pushed, contents and messages | `who-data-gate.py --range … --strict` |

`--strict` makes a missing private strain list a failure rather than a warning. The list
is found at `$WHO_STRAIN_LIST`, else `$ACMACS_DATA/.who-strain-list`, else
`../acmacs-data/.who-strain-list` (it is never stored in this repo).

**Never bypass the hooks with `--no-verify`.**

## What it cannot see

The gate skips binary and compressed files (`.ace`, `.xz`, `.br`, `.pdf`, `.png`, …),
because it cannot read them. Those are blocked by `.gitignore` instead. Keep both: the
gitignore stops binary data, and the gate stops data pasted into text, code and messages.

## Test data

Real `.ace` / FASTA fixtures belong in the private data repo, located at test time, with
tests skipping when it is absent. Synthetic fixtures are generated by test code with
invented names, not committed as files.

## Changing the allowlist or baseline

`tools/who-data-gate-allowlist.txt` holds only invented placeholders and published clade
designations. A real strain name never goes there. `tools/who-data-gate-baseline.txt`
starts empty. acmacs-f has no historic files to grandfather, and should stay that way.
